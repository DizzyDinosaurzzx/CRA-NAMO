# CRA-NAMO

**Cost- and Risk-Aware Online Navigation in Dynamic Maps with Movable Obstacles**

CRA-NAMO 是一个面向可移动障碍物导航（Navigation Among Movable Obstacles, NAMO）的二维仿真研究项目。系统需要在环境信息不完全的条件下在线感知、规划和执行，并在绕行与搬移障碍物之间权衡机器人运动成本、障碍物搬移功、任务时间和操作风险。

> 项目状态：研究原型，仍在开发中。当前代码已经实现在线感知—规划—执行—再规划闭环，以及机器人主动搬移导致的地图变化；障碍物自主运动、定时事件和状态突变等完整动态地图机制尚未实现。因此，当前版本更准确地说是**部分可观测准静态地图中的在线风险感知 NAMO**，而不是完整的动态环境导航系统。

## 研究问题

给定起点、目标点、已知静态几何和初始未知的可移动障碍物，机器人需要回答两个相互关联的问题：

1. 应该绕过障碍物，还是将它移开？
2. 如果需要移动，怎样兼顾可行性、能耗、时间与风险？

当前实现使用如下总代价：

```text
C = (1 - w) J + w · p_t · T + R
J = λD + W
```

其中：

- `D`：机器人总行驶距离，包括与障碍物保持接触时的移动；
- `λ`：单位行驶距离的等效阻力，单位为 N，使 `λD` 具有能量单位；
- `W`：搬移障碍物所做的功，由估计/真实摩擦力与障碍物 SE(2) 路径共同计算；
- `T`：运动、转向和在线规划共同占用的模拟时间；
- `p_t`：将时间换算为能量的系数 `time_value`，单位为 J/s；
- `w ∈ [0, 1]`：能量与时间的权衡系数；
- `R`：移动高风险物体产生的附加代价，每个障碍物只计费一次，并且不随 `w` 被折减。

## 当前已实现

- **在线部分可观测导航**：机器人仅根据感知半径和视线遮挡更新 belief，不允许规划器直接读取完整真实世界；每执行若干条边后重新感知和规划。
- **路径与操作联合决策**：在均匀栅格 roadmap 上进行带分支限界的最佳优先搜索，将普通移动和清障动作纳入同一搜索代价。
- **SE(2) 障碍物搬移规划**：同时考虑障碍物平移、旋转、扫掠区域、静态墙体以及其他已知障碍物碰撞。
- **机器人—障碍物接触约束**：搬移期间机器人需要到达抓持位置、沿障碍物边界保持接触，并在释放后重新连接到 roadmap。
- **难度估计**：根据物体标签、尺寸和材质估计摩擦力；可调用 DeepSeek，也可在无密钥时退化为内置启发式估计。
- **两阶段风险评估**：首次观察时根据可见标签评估风险，物理接触获得真实信息后重新评估；支持 `low` 到 `extreme` 五档风险。
- **运动学时间模型**：区分空载/负载下的线速度、线加速度、角速度和角加速度，并把实际规划耗时计入统一时间轴。
- **碰撞驱动的知识更新**：机器人或被搬物体撞上未知物体时记录新信息并触发重新规划。
- **结果可视化**：输出路径、障碍物位姿、估计/真实搬移难度、风险等级和代价统计；可按模拟时间生成 GIF。
- **LLM 基准实验**：仓库包含难度估计准确性、敏感性、导航代价影响等实验脚本和历史结果。

在线闭环如下：

```text
局部感知 → 更新 belief → 代价/风险感知规划 → 执行一段路径或搬移动作
    ↑                                                   ↓
    └──────── 新障碍、接触信息或碰撞 → 重新规划 ────────┘
```

## 尚未完成的 Dynamic 部分

当前世界中的障碍物不会在机器人操作之外自主改变。计划中的完整动态地图至少还需要：

- 障碍物按时间脚本自主平移和旋转；
- 由机器人位置、搬移动作或其他条件触发的环境事件；
- 障碍物标签、尺寸、搬移难度和风险属性随事件变化；
- 动态事件只修改真实世界，机器人仍需通过感知发现变化；
- 在规划和执行阶段进行时空碰撞预测，而不只是对当前几何快照规划；
- 对移动目标/障碍物进行轨迹预测、不确定性建模和安全重规划；
- 建立动态场景指标，例如碰撞率、最小安全间距、事件响应延迟和动态任务成功率。

在这些功能完成前，实验结论应限定为：**未知但静止的障碍物，以及由机器人自身操作造成变化的在线 NAMO 场景**。

## 环境安装

建议使用 Python 3.10 或更高版本。虽然 `requirements.txt` 的注释写有 Python 3.9，但源码使用了 Python 3.10 引入的 `X | None` 类型语法。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

主要依赖包括 Shapely、NumPy、SciPy、Matplotlib、Pillow 和 Requests。

## 安全配置与运行模式

LLM 不是几何规划本身的必要条件。`DifficultyEstimator` 和 `RiskEstimator` 在没有 API Key 时会使用内置启发式规则。

当前开发版本的 `CRA-NAMO/config.py` 中仍包含明文 DeepSeek API Key。**在公开仓库或继续实验前，应立即撤销该密钥、将默认值改为空字符串，并仅通过环境变量提供新密钥：**

```bash
export DEEPSEEK_API_KEY="your-key"
```

请勿将真实密钥提交到 Git。另请注意，`--no-llm-order` 只关闭搜索中的 LLM 排序偏置，并不会关闭难度估计和风险评估所需的 LLM 调用；完全离线运行需要确保配置与环境中均没有 API Key。

## 快速开始

所有运行命令从仓库根目录执行：

```bash
# 查看可用参数和场景
python CRA-NAMO/main.py --help

# 默认 corridor 场景
python CRA-NAMO/main.py --scenario corridor

# 复杂策略演示：风险绕行、隐藏障碍物、接触后重新评估
python CRA-NAMO/main.py --scenario strategy_demo

# shortest 策略忽略障碍物搬移功 W（仍保留机器人路程和风险项）
python CRA-NAMO/main.py --scenario corridor --strategy shortest

# 调整能量—时间权衡；0 为纯能量，1 为纯时间
python CRA-NAMO/main.py --scenario corridor --time-importance 0.5

# 显式请求按模拟时间采样的 GIF（见下方关于当前默认值的说明）
python CRA-NAMO/main.py --scenario corridor --frames
```

运行结束后，终端会报告是否到达目标、总代价 `C`、能量代价 `J`、风险附加项、移动障碍物编号、重规划次数、模拟运动时间、规划时间、搜索扩展数及 LLM 调用次数。可视化结果默认保存到 `img/`。当前 `Config.save_frames` 的默认值为 `True`，因此即使不传 `--frames` 也会生成 GIF；现有 `--frames` 开关实际是冗余的。如需关闭，应在场景配置中将 `save_frames` 设为 `False`。

当前自动注册的场景为：

| 场景 | 用途 | 规模 |
| --- | --- | --- |
| `corridor` | 基础走廊与单个大型可移动障碍物，主要展示 SE(2) 搬移 | 4 个静态、1 个可移动障碍物 |
| `strategy_demo` | 展示风险绕行、隐藏障碍、接触后风险更新和回退决策 | 11 个静态、7 个可移动障碍物 |
| `maze_doors_complex` | 大规模多门迷宫与搜索压力测试 | 50 个静态、63 个可移动障碍物 |

## 添加新场景

在 `CRA-NAMO/scenarios/` 中创建 Python 模块，并提供无参数的 `create()` 函数。返回字典必须包含：

```python
{
    "workspace": workspace_polygon,
    "static": static_obstacles,
    "movable": movable_obstacles,
    "start": (x_start, y_start),
    "goal": (x_goal, y_goal),
    "cfg": Config(),
}
```

场景会被 `scenarios/registry.py` 自动发现，无需手工登记。文件名即 `--scenario` 使用的名称。

## 关键参数

主要参数集中在 `CRA-NAMO/config.py`：

| 参数 | 含义 | 默认值 |
| --- | --- | ---: |
| `robot_radius` | 圆形机器人半径 | `0.2 m` |
| `lambda_distance` | 单位机器人路程的等效阻力 `λ` | `350 N` |
| `time_importance` | 时间在综合目标中的权重 `w` | `0.0` |
| `time_value` | 时间—能量换算系数 `p_t` | `100 J/s` |
| `risk_weight` | 风险附加项倍率 | `1.0` |
| `R_perc` | 感知半径 | `10.0 m` |
| `R_manip` | 单次可搜索的障碍物搬移范围 | `5.0 m` |
| `grid_step` | roadmap 采样间距 | `0.3 m` |
| `conn_radius` | roadmap 连边半径 | `0.6 m` |
| `step_execute_edges` | 每次重规划前最多执行的普通边数 | `1` |
| `se2_cell` | 障碍物 SE(2) 平移网格分辨率 | `0.15 m` |
| `se2_n_theta` | 障碍物角度离散数 | `12` |

命令行目前只覆盖其中一部分参数；其余参数需要通过场景中的 `Config` 实例调整。

## 当前限制

- 尚无自主移动障碍物和事件调度器，不能验证真正动态环境中的安全性与完备性。
- 机器人使用二维圆盘模型，操作对象使用二维矩形足迹；接触与搬移仍是几何/准静态近似。

- 搬移功主要按摩擦力乘 SE(2) 等效距离计算，旋转做功、接触力、力矩、抓持稳定性和惯性尚未精细建模。

- 搜索状态主要以 roadmap 节点为核心，规划阶段没有完整携带机器人朝向；执行时才结算真实转向时间，因此预测目标与执行统计并不完全一致。
- LLM 服务会引入网络延迟、费用和非确定性；现有 benchmark 规模有限，不能替代跨场景统计验证。
- 当前仓库没有自动化测试、持续集成、固定依赖版本或标准打包配置，回归验证仍主要依赖场景运行。
- 大场景的均匀 roadmap、逐边清障评估和 SE(2) 搜索计算量较高，尚缺系统的性能基准与剖析。

## 建议的下一步

1. 先移除并撤销仓库中的明文密钥，增加 `.env.example` 或纯环境变量配置。
2. 把动态事件设计成只作用于真实世界的时间有序队列，在执行器推进统一时钟时触发，保持 world/belief 严格隔离。
3. 将规划状态扩展到时间维度或采用短时预测窗口，使机器人能检查未来占据而非当前几何快照。
4. 为 cost、visibility、碰撞、风险重评、SE(2) 路径和在线重规划补充单元测试与确定性回归场景。
5. 明确区分“规划目标值”“执行后真实代价”和“墙钟规划耗时”，并建立统一的实验记录格式。
6. 增加纯启发式、LLM、oracle、无风险项、无时间项等消融实验，并用多随机种子报告均值和方差。

## 研究使用说明

这是面向算法验证的仿真原型，不应直接用于真实机器人或安全关键环境。当前仓库未提供许可证；在复用或发布代码前，建议补充明确的开源许可证、引用信息和实验复现版本号。
